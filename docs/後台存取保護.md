# 後台存取保護

> 規格 D16：單一管理員，密碼＋Email 驗證碼（2026-10-27 由驗證器 App 改為寄信，比較好用）。對應規格第 7、10 節。

## 原則

1. **擋資料，不只擋畫面。** 後台頁面的 JS 檔是公開靜態檔；真正要保護的是 `/api/admin/*` 與頁面資料請求（`*.data`）。保護範圍一律是 `/admin*` **和** `/api/admin*`。
2. **在伺服器擋。** 檢查在 Worker 進 React Router 之前（`workers/auth/admin.ts`），前端隱藏選單不算安全機制。
3. **沒設定就擋（fail closed）。** 密碼、session 兩個 secret 沒設齊時，部署環境的後台一律 404。
4. **一個人不需要資料庫。** 密碼雜湊、session 金鑰存 Worker secret，寄出的驗證碼只簽在 cookie 裡；你擁有 Cloudflare 帳號，重設 secret 就是「忘記密碼」流程。

## 運作方式

```
/admin/login
  1. POST /api/admin/session {password}
     ├─ 密碼對：寄 6 位數驗證碼到 service@andelni.com（Cloudflare Email Routing 轉店家 Gmail）
     │          回 202，發 cookie andelni_admin_otp（驗證碼的簽章，10 分鐘）
     └─ 密碼錯：401
  2. POST /api/admin/session {password, code}
     ├─ 都對：發 cookie andelni_admin（HttpOnly、Secure、SameSite=Lax，7 天），清掉 otp cookie
     ├─ 任一錯：「密碼或驗證碼錯誤」（不說是哪個錯）
  └─ 同一 IP 每分鐘超過 5 次：429

/admin*、/api/admin* 每個請求：
  cookie 有效 → 交給 React Router／API
  cookie 無效 → 頁面 302 到 /admin/login?next=…
                資料請求（*.data）回 React Router 認得的轉址
                API 回 401
```

| 項目     | 做法                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| 密碼     | PBKDF2-SHA256、100,000 次、加鹽（規格 3.6）；存 `ADMIN_PASSWORD_HASH`                              |
| 兩步驟   | Email 6 位數驗證碼（Resend，`RESEND_API_KEY`）；cookie 存 HMAC(到期＋驗證碼＋密碼雜湊)，不存資料庫 |
| Session  | cookie 值＝到期時間＋HMAC-SHA256 簽章（`SESSION_SECRET`），簽章含密碼雜湊，換密碼後舊登入自動失效  |
| 頻率限制 | Workers Rate Limiting binding `ADMIN_LOGIN_LIMIT`（`wrangler.jsonc`）                              |
| CSRF     | cookie `SameSite=Lax`；登入 API 只收 `application/json`                                            |
| 搜尋引擎 | 後台回應加 `X-Robots-Tag: noindex`、`Cache-Control: no-store`                                      |

## 第一次設定

在**自己的終端機**執行（不要在 Claude 對話裡用 `!` 跑，密碼會留在對話紀錄）：

```sh
npx wrangler login                     # 若尚未登入
pnpm admin:setup                       # 正式站；staging 加 --env=staging
npx wrangler secret put RESEND_API_KEY # 寄驗證碼用；staging 加 --env staging
```

`admin:setup` 會請你輸入後台密碼（至少 10 碼；留空就自動產生並印一次），另外產生 session 金鑰，寫入 Cloudflare。secret 寫入後立即生效，不用重新部署。到 `/admin/login` 輸入密碼 → 收信 → 輸入 6 位數驗證碼。

## 日常維運

| 情況                   | 指令                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 忘記密碼／密碼可能外洩 | `pnpm admin:setup --only=password`（所有已登入裝置同時失效）                                                                          |
| 強制所有裝置登出       | `pnpm admin:setup --only=session`                                                                                                     |
| 本機用正式流程測試     | `pnpm admin:setup --local` → `pnpm build && npx vite preview`（寫入 `.dev.vars`，不進 Git；沒設 `RESEND_API_KEY` 時驗證碼印在終端機） |

`pnpm dev` 本機開發時沒有 `.dev.vars` 就直接放行後台，方便開發。部署環境沒設 `RESEND_API_KEY` 時，登入第一步回 503。

## 已知限制（ponytail）

- 驗證碼不存資料庫，10 分鐘內同一組可重複使用（要同時有密碼和那個 cookie 才有用）；要一次性需記在 D1／KV。
- 驗證碼寄到 `service@andelni.com`（寫在 `workers/auth/admin.ts`），靠 Cloudflare Email Routing 轉到 Gmail；改轉寄規則前先確認後台還收得到信。
- 只有一個管理員帳號。若之後有多位員工、權限不同（例如出貨人員不能看成本），再加 D1 `admins (email, password_hash, role)` 表，或改用 Cloudflare Access 搭配角色表。
- 正式站掛上自有網域後，`wrangler.jsonc` 設 `"workers_dev": false`，只留一個入口。

## 驗證方式

- `pnpm test`：密碼雜湊、路徑判斷、寄碼／驗碼／過期、登入／登出／過期／竄改／換密碼失效、頻率限制、非 JSON 拒收、沒設寄信金鑰回 503。
- 手動：無痕視窗開 `/admin/orders` 應轉到登入頁；錯誤密碼顯示錯誤；收信輸入驗證碼後回到原頁；`curl /api/admin/...` 未帶 cookie 應 401。
