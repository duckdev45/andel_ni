# 後台存取保護

> 規格 D16：單一管理員，密碼＋驗證器 App（TOTP）。對應規格第 7、10 節。

## 原則

1. **擋資料，不只擋畫面。** 後台頁面的 JS 檔是公開靜態檔；真正要保護的是 `/api/admin/*` 與頁面資料請求（`*.data`）。保護範圍一律是 `/admin*` **和** `/api/admin*`。
2. **在伺服器擋。** 檢查在 Worker 進 React Router 之前（`workers/auth/admin.ts`），前端隱藏選單不算安全機制。
3. **沒設定就擋（fail closed）。** 三個 secret 沒設齊時，部署環境的後台一律 404。
4. **一個人不需要資料庫。** 密碼雜湊、驗證器金鑰、session 金鑰都存 Worker secret；你擁有 Cloudflare 帳號，重設 secret 就是「忘記密碼」流程。

## 運作方式

```
/admin/login：密碼＋驗證器 App 6 位數碼 → POST /api/admin/session
  ├─ 兩者都對：發 cookie andelni_admin（HttpOnly、Secure、SameSite=Lax，7 天）
  ├─ 任一錯：「密碼或驗證碼錯誤」（不說是哪個錯）
  └─ 同一 IP 每分鐘超過 5 次：429

/admin*、/api/admin* 每個請求：
  cookie 有效 → 交給 React Router／API
  cookie 無效 → 頁面 302 到 /admin/login?next=…
                資料請求（*.data）回 React Router 認得的轉址
                API 回 401
```

| 項目     | 做法                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 密碼     | PBKDF2-SHA256、100,000 次、加鹽（規格 3.6）；存 `ADMIN_PASSWORD_HASH`                             |
| 兩步驟   | RFC 6238 TOTP（SHA-1、30 秒、6 位數），容許前後 30 秒；存 `ADMIN_TOTP_SECRET`                     |
| Session  | cookie 值＝到期時間＋HMAC-SHA256 簽章（`SESSION_SECRET`），簽章含密碼雜湊，換密碼後舊登入自動失效 |
| 頻率限制 | Workers Rate Limiting binding `ADMIN_LOGIN_LIMIT`（`wrangler.jsonc`）                             |
| CSRF     | cookie `SameSite=Lax`；登入 API 只收 `application/json`                                           |
| 搜尋引擎 | 後台回應加 `X-Robots-Tag: noindex`、`Cache-Control: no-store`                                     |

## 第一次設定

在**自己的終端機**執行（不要在 Claude 對話裡用 `!` 跑，密碼會留在對話紀錄）：

```sh
npx wrangler login        # 若尚未登入
pnpm admin:setup
```

腳本會產生 24 字隨機密碼、驗證器金鑰、session 金鑰，寫入 Cloudflare，並**只印一次**：

- 後台密碼 → 存進密碼管理器
- 驗證器金鑰 → 在 Google Authenticator／1Password 選「手動輸入金鑰」，或把 `otpauth://` 網址貼進 1Password

然後部署（`pnpm run deploy`），到 `/admin/login` 登入。

## 日常維運

| 情況                   | 指令                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| 忘記密碼／密碼可能外洩 | `pnpm admin:setup --only=password`（所有已登入裝置同時失效）                                |
| 換手機／驗證器遺失     | `pnpm admin:setup --only=totp`                                                              |
| 強制所有裝置登出       | `pnpm admin:setup --only=session`                                                           |
| 本機用正式流程測試     | `pnpm admin:setup --local` → `pnpm build && npx vite preview`（寫入 `.dev.vars`，不進 Git） |

`pnpm dev` 本機開發時沒有 `.dev.vars` 就直接放行後台，方便開發。

## 已知限制（ponytail）

- 同一組驗證碼在約 90 秒內可重複使用；要防重放需記住最後用過的時間區間（D1／KV），接後端後可加。
- 只有一個管理員帳號。若之後有多位員工、權限不同（例如出貨人員不能看成本），再加 D1 `admins (email, password_hash, totp_secret, role)` 表，或改用 Cloudflare Access 搭配角色表。
- 正式站掛上自有網域後，`wrangler.jsonc` 設 `"workers_dev": false`，只留一個入口。

## 驗證方式

- `pnpm test`：RFC 6238 測試向量、密碼雜湊、路徑判斷、登入／登出／過期／竄改／換密碼失效、頻率限制、非 JSON 拒收。
- 手動：無痕視窗開 `/admin/orders` 應轉到登入頁；錯誤密碼顯示錯誤；正確登入回到原頁；`curl /api/admin/...` 未帶 cookie 應 401。
